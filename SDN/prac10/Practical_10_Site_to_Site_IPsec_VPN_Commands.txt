===============================================================
10. R1 - CONFIGURE INTERESTING TRAFFIC ACL 110
===============================================================

enable
configure terminal

access-list 110 permit ip 192.168.1.0 0.0.0.255 192.168.3.0 0.0.0.255

end

This identifies traffic from the R1 LAN to the R3 LAN as interesting
traffic.

The implicit deny means other traffic is not encrypted by this ACL.

===============================================================
11. R1 - IKE PHASE 1 ISAKMP POLICY
===============================================================

enable
configure terminal

crypto isakmp policy 10
encryption aes 256
authentication pre-share
group 5
exit

crypto isakmp key vpnpa55 address 10.2.2.2

end

Important values:

Policy:
10

Encryption:
AES 256

Authentication:
Pre-share

DH:
Group 5

Shared key:
vpnpa55

Peer:
10.2.2.2

===============================================================
12. R1 - IKE PHASE 2 TRANSFORM SET
===============================================================

enable
configure terminal

crypto ipsec transform-set VPN-SET esp-aes esp-sha-hmac

end

This creates:

Transform-set name:
VPN-SET

Encryption:
esp-aes

Authentication:
esp-sha-hmac

===============================================================
13. R1 - CREATE CRYPTO MAP
===============================================================

enable
configure terminal

crypto map VPN-MAP 10 ipsec-isakmp
description VPN connection to R3
set peer 10.2.2.2
set transform-set VPN-SET
match address 110
exit

end

The crypto map connects together:

Peer:
10.2.2.2

Transform set:
VPN-SET

Interesting traffic:
ACL 110

===============================================================
14. R1 - APPLY CRYPTO MAP TO OUTGOING INTERFACE
===============================================================

enable
configure terminal

interface serial0/0/0
crypto map VPN-MAP
exit

end

IMPORTANT:
The source explicitly binds VPN-MAP to R1 S0/0/0.

23. PART 3 - VERIFY THE VPN BEFORE INTERESTING TRAFFIC
===============================================================

On R1:

show crypto ipsec sa

Before interesting traffic, the source says the packet counters
should be 0.

Look for:

packets encapsulated
packets encrypted
packets decapsulated
packets decrypted

They should initially be 0.

===============================================================
24. CREATE INTERESTING TRAFFIC
===============================================================

From PC-A:

ping 192.168.3.3

This is interesting traffic because:

Source:
192.168.1.0/24

Destination:
192.168.3.0/24

This traffic should trigger the IPsec VPN.

===============================================================
25. VERIFY IPsec AFTER INTERESTING TRAFFIC
===============================================================

On R1:

show crypto ipsec sa

The source says the packet counters should now be greater than 0.

This indicates that traffic is being encapsulated/encrypted and
decapsulated/decrypted through the VPN.

===============================================================
26. CREATE UNINTERESTING TRAFFIC
===============================================================

From PC-A:

ping 192.168.2.3

This traffic is between:

192.168.1.0/24

and

192.168.2.0/24

It does NOT match ACL 110.

Therefore, it should NOT trigger IPsec encryption.

===============================================================
27. VERIFY UNINTERESTING TRAFFIC
===============================================================

On R1:

show crypto ipsec sa

The source says the packet counters should NOT change after the
uninteresting PC-A -> PC-B ping.

This verifies that traffic not matching ACL 110 is not encrypted.

===============================================================
28. IMPORTANT: ROUTER PING IS NOT INTERESTING TRAFFIC
===============================================================

The source specifically notes:

Ping from R1 to PC-C is NOT interesting traffic.

Ping from R3 to PC-A is NOT interesting traffic.

Why?

The ACL matches LAN-to-LAN traffic:

192.168.1.0/24 -> 192.168.3.0/24

It does not match traffic sourced from the router itself.

For the lab test, use:

PC-A -> PC-C

===============================================================

security association.

The exact state/output can vary by Packet Tracer version, so use the
actual device output rather than expecting an identical timer/state.

R1:

STEP 4:

R1:

R3:

access-list 110 permit ip 192.168.1.0 0.0.0.255 192.168.3.0 0.0.0.255

===============================================================
34. TROUBLESHOOTING - IKE DOES NOT FORM
===============================================================

Check both sides use:

AES 256
Pre-share
DH group 5
Key vpnpa55

R1:

crypto isakmp policy 10
encryption aes 256
authentication pre-share
group 5

crypto isakmp key vpnpa55 address 10.2.2.2

R3:

crypto isakmp policy 10
encryption aes 256
authentication pre-share
group 5

crypto isakmp key vpnpa55 address 10.1.1.2

Also verify peer addresses are correct.

===============================================================
35. TROUBLESHOOTING - IPsec COUNTERS STAY AT ZERO
===============================================================

First generate the correct traffic:

PC-A:
ping 192.168.3.3

Then check:

R1:
show crypto ipsec sa

If counters stay at zero, verify:

1. ACL 110
2. Crypto map
3. Peer address
4. Transform set
5. Crypto map applied to Serial0/0/0
6. R3 crypto map applied to Serial0/0/1

===============================================================
36. TROUBLESHOOTING - UNINTERESTING TRAFFIC CHANGES COUNTERS
===============================================================

Test:

PC-A:
ping 192.168.2.3

Then:

R1:
show crypto ipsec sa

The source expects the VPN counters not to change from this traffic.

If they do, check whether ACL 110 was configured incorrectly.

41. SOURCE-SPECIFIC NOTES
===============================================================

1. The source says R2 is a pass-through router and has no knowledge
   of the VPN.

2. The source says the VPN tunnel is R1 to R3 through R2.

3. The source specifies AES 256, SHA-1, pre-shared authentication,
   DH group 5, and 86400-second IKE SA lifetime.

4. The source says Packet Tracer currently supports DH group 5 and
   notes that production networks should use at least DH 14.

5. The source says the R3 crypto-map interface step is not graded,
   but it is included in this practical TXT because the command is
   part of the source lab.

6. The source says completion should be 100% under Check Results.
