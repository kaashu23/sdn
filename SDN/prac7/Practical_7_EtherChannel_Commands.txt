3. IMPORTANT ETHERCHANNEL RULE
============================================================

The practical recommends shutting down the physical interfaces before
adding them to the channel-group. This helps prevent EtherChannel
Misconfig Guard from placing ports into err-disabled state.

All ports in the same EtherChannel should have compatible settings:
- Same speed and duplex
- Same access/trunk configuration
- Same native VLAN if trunking
- Same allowed VLANs if trunking

21. STP AND ETHERCHANNEL
============================================================

EtherChannel does NOT stop Spanning Tree Protocol from detecting
switching loops.

STP treats the EtherChannel as one logical link.

Check:

show spanning-tree active

The practical's example shows:

Po1 = Root FWD
Po2 = Alternate BLK

Because STP may block one logical path, some physical links can be
blocked as part of the logical topology.

============================================================
22. MAKE S1 PRIMARY ROOT FOR VLAN 1
============================================================

The practical explains that Port Channel 2 may not initially be
operative because STP can place the Gigabit EtherChannel in blocking.

To make S1 the primary root:

============================================================
28. ETHERCHANNEL MODE REVISION
============================================================

PAgP:

desirable = actively negotiates PAgP
auto      = waits for PAgP

Compatible PAgP:
desirable + desirable
desirable + auto

auto + auto:
EtherChannel will NOT form.

LACP:

active  = actively negotiates LACP
passive = waits for LACP

Compatible LACP:
active + active
active + passive

passive + passive:
EtherChannel will NOT form.

Static:

on = EtherChannel without PAgP/LACP negotiation

============================================================
29. IMPORTANT ETHERCHANNEL GUIDELINES
============================================================

1. EtherChannel supports up to eight Ethernet interfaces.

2. Interfaces in an EtherChannel must operate at the same speed and
   duplex.

3. EtherChannel can be used for access ports or trunk links.

4. All Layer-2 EtherChannel member interfaces must have compatible
   VLAN/trunk configuration.

5. Trunk EtherChannels must have matching native VLANs.

6. Trunk EtherChannels must have matching allowed VLANs.

7. Shut down physical interfaces before creating the EtherChannel.

8. After configuration, verify that interfaces are up/up and bundled.

9. Channel-group numbers are local to each switch. They do not have
   to match on both ends, although this practical uses matching numbers.

============================================================
30. COMMON ERRORS AND FIXES
============================================================

ERROR:
EtherChannel does not form.

CHECK:

show etherchannel summary

Make sure both ends use compatible modes.

PAgP:
desirable + desirable
or
desirable + auto

LACP:
active + active
or
active + passive

------------------------------------------------------------

ERROR:
Ports show as suspended/stand-alone.

CHECK:

show etherchannel summary

Then verify that member ports have matching trunk settings.

------------------------------------------------------------

ERROR:
Port becomes err-disabled.

Try:

interface range <member-ports>
shutdown
no shutdown

Then check:

show etherchannel summary

------------------------------------------------------------

ERROR:
Trunk is not active.

Check:

show interfaces trunk

Then configure the logical interface:

interface port-channel <number>
switchport mode trunk

------------------------------------------------------------

ERROR:
One EtherChannel is blocked by STP.

Check:

show spanning-tree active

If required by the practical, make S1 the root:

spanning-tree vlan 1 root primary

Then verify again.
