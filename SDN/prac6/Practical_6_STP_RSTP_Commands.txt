PORT-BY-PORT CONNECTIONS:

TIP:
First build exactly these 5 links. Then configure the switches.
The two links from D1 to A1 and the two links from D2 to A1 create
redundant Layer-2 paths. STP/RSTP will prevent a Layer-2 loop.

============================================================

============================================================
1. TOPOLOGY / CONNECTIONS
============================================================

Use 3 switches:

D1 = Distribution Switch 1
D2 = Distribution Switch 2
A1 = Access Switch 1

Physical connections shown in the practical:

D1 G1/0/1  <-->  D2 G1/0/1

D1 G1/0/5  <-->  A1 F0/1
D1 G1/0/6  <-->  A1 F0/2

D2 G1/0/5  <-->  A1 F0/3
D2 G1/0/6  <-->  A1 F0/4

This creates redundant Layer-2 paths. STP prevents the loop by placing
one or more redundant ports into a blocking/alternate state.

NOTE:
The source lab also shows:

On switch models that support the command, it can be entered before
switchport mode trunk. Some Cisco Catalyst models already use 802.1Q
by default and do not accept that command. If Packet Tracer reports
"Invalid input", omit only that command and continue with
switchport mode trunk.

11. PART 2 - DISCOVER DEFAULT SPANNING TREE
============================================================

All switches are initially running:

spanning-tree mode pvst

The practical asks you to observe:
1. Root Bridge
2. Root Ports
3. Designated Ports
4. Alternate/blocked ports
5. Topology changes when a link is shut down

============================================================
12. FIND THE ROOT BRIDGE
============================================================

On A1:

show spanning-tree root

The practical's documented output shows D1 as the root bridge for
VLAN 1 and VLAN 2.

Also run on D1:

show spanning-tree root

And on D2:

show spanning-tree root

To inspect the MAC addresses:

show version | include MAC

Run this command on D1, D2 and A1.

The root bridge election uses the Bridge ID. With equal default
priorities, the lower base MAC address is used as the tie breaker.

============================================================
13. VIEW COMPLETE SPANNING TREE
============================================================

On A1:

show spanning-tree

Look for the Interface Role and Status columns.

Typical roles are:

Root  = Root Port
Desg  = Designated Port
Altn  = Alternate Port

Typical states include:

FWD   = Forwarding
BLK   = Blocking

The practical documents A1 F0/1 as the root port and the redundant
A1 links as alternate/blocked paths in the initial topology.

============================================================
14. OBSERVE ROOT PORT INFORMATION
============================================================

On D1:

show spanning-tree root

On D2:

show spanning-tree root

On A1:

show spanning-tree root

The practical explains that the root port is the port with the lowest
path cost toward the root bridge.

The documented example shows:

D1 = Root Bridge
D2 root port = Gi1/0/1
A1 root port = Fa0/1

============================================================
15. OBSERVE PORT COST AND PATH COST
============================================================

On A1:

show spanning-tree

The practical example shows a FastEthernet path cost of 19.

When a topology change forces D2 to reach D1 through A1, the documented
example shows:

Root path cost = 38
Root port cost = 19

This is because two FastEthernet links are involved:

19 + 19 = 38

============================================================
19. PART 3 - OBSERVE STP DEBUG EVENTS
============================================================

On D2:

enable

debug spanning-tree events

Then:

configure terminal

interface gigabitethernet1/0/1
shutdown
exit

The debug output will show the spanning-tree reaction to the link
failure.

The practical's example shows:
- D2 detects G1/0/1 going down.
- D2 changes its root path.
- D2 uses G1/0/5.
- G1/0/6 transitions toward blocking.
- Topology Change Notifications are generated.

The lab documents approximately 17 seconds for the traditional
spanning-tree topology adjustment in its example.

============================================================
22. IMPORTANT RSTP POINT
============================================================

The practical explains that RSTP does not provide the full rapid
convergence benefit when only one switch is running RSTP.

If D1 is running rapid-pvst but D2 and A1 are still running PVST,
compatibility behavior can cause traditional STP timing to be used.

Therefore, configure all switches for rapid-pvst.

============================================================
32. IMPORTANT PRACTICAL NOTES
============================================================

1. The initial configuration uses PVST as specified in the lab.

2. VLAN 2 is created and named SecondVLAN even though the main
   addressing table uses VLAN 1 for management.

3. The redundant links are intentional. STP prevents Layer-2 loops.

4. D1 is the documented root bridge in the example output.

5. A1's redundant links can appear as Alternate/Blocking ports.

6. When a root link fails, STP selects another available path.

7. RSTP is enabled using:

   spanning-tree mode rapid-pvst

8. RSTP must be enabled across the participating switches to get the
   intended rapid convergence behavior.

9. If debug output is enabled, disable it after the observation:

   undebug all

10. Interface names must match the actual switch model in Packet Tracer.
    If your model uses different interface numbering, use the equivalent
    interfaces shown by:

    show ip interface brief
